# Common ability selection boundary

Ticket22I1 provides `ability_selections.select_abilities` and `project_abilities` for game adapters. It composes the existing selectors, allowance accounting, ordinary retained formulas, descriptive parameters, requirements and additive skill effects. It contains no class, race, spell or power name dispatch.

An `abilities-v1` catalog has exactly `id`, `version`, `game`, `format`, `options` and `groups`. Games remain `rifts` or `heroes-unlimited`. Each option needs a unique `id`, `name`, book/section `source` and nonempty `description`. Optional `category`, `tags`, `parameters`, `requirements`, `acquisition_formulas` and `skill_effects` use the existing shared contracts. Every option, including inactive options, preflights before dice. Ordinary acquisition formulas are named groups; options without formulas retain an empty receipt.

Each group needs unique `id`, `name`, book/section `source`, `count` and a shared `selector`; optional `costs` reference only eligible options. Groups independently account for the selected set. Overlapping groups deliberately credit the same option independently; an adapter must declare the actual entitlement structure rather than treating these as automatic allocation buckets. Multi-category path rules and alternative allowances still belong in declarative path composition to be integrated next.

State has exactly `pin`, `selections`, and `acquisitions`. The pin includes catalog identity/version/game and SHA256 over the canonical catalog plus supplied skill catalog. This guards replay against changed descriptions, formulas, source evidence and selector dependencies. It complements the application's RuleArchive pins; it does not activate or certify a source import. Inputs are copied, inactive receipts retained, and every cached receipt validated on each selection or projection. Unknown/duplicate selections and missing receipts reject; known choices outside an allowance and unmet requirements remain available with guidance and no override marker.

Callers supply current level, effective attributes, same-game skill catalog and optionally acquired `skill_selections`. Requirements can refer to `abilities` or `skills`. Projections return descriptions, parameters, requirement evidence, group remaining counts, acquired formula values and compiled `skill_effects`. Effect identities encode the option/effect pair to preserve colliding display names. Combined bonuses must stay in the supported exact integer range. Adapters must feed the contributions into their normal percentage engine and retain its final-total bounds and cap rules.

This slice is an engine contract proven by synthetic psychic, spell and mutant fixtures. It makes no accepted archive, browser, PDF or portable character schema changes. The next integration must add an ordinary Rifts psionic path, retained effective-M.E. ISP contribution and level gains, exact application/archive pins, save/import validation, browser choices and editable sheet descriptions. Synthetic fixture replay through JSON is not a claim that portable character import already recognizes this state. Magic, wider powers, all supplied class/race options and robot/bionic design remain required.

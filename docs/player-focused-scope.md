# Player-focused scope amendment

Confirmed by the user on 2026-10-05. This amendment supersedes conflicting detail in the original specification, ticket plan and older mechanical contracts. Preserve the original plan for the final retrospective, but assess delivery against this agreed scope.

## Required outcome

Build an enjoyable offline Windows character creator for Rifts and Heroes Unlimited. Prioritize access to supplied character options, prescribed attribute generation and house rules, race/class/background-driven skill grants and selection counts, resulting skill percentages and advancement, ability selection, categorized equipment, editable sheets and reliable saves. Use shared data-driven class/race/ability definitions rather than handlers for individual options.

Calculate each acquired skill's normal displayed percentage, including applicable education, attribute, class/race, power and level bonuses. The user means the usable skill percentage; preserve relevant bonuses rather than displaying only a book's unmodified base value. Do not expand a skill into every situational check, activity rate or action variant.

## Details that do not gate delivery

Do not build or complete exhaustive kick/punch/maneuver calculations, conditional attack combinations, swimming/climbing/running speeds, activity endurance, fatigue simulations or similarly fine-grained effects. Represent such rules with concise descriptions when helpful. Powers, spells and psionics can retain descriptive range/duration/cost/effect information without an encounter simulator or automatic resolution of every effect. Already working calculations may remain available; extending them is lower priority and is not a release prerequisite.

An option is not incomplete solely because these optional details are descriptive. Missing required attributes, skill entitlements/percentages, meaningful selection support, persistence or sheet export are still material gaps. Source inventory continues to distinguish actual missing content from optional calculations.

## Explicit exclusions and retained construction

General core-book insanity systems and tables are excluded. Preserve option-specific traits such as the Crazy O.C.C. and permanent injuries; concise descriptions are acceptable, especially for ambiguous game effects. Do not create a general insanity generator or automatically display its saving charts.

Heroes Unlimited Mega Heroes are excluded. This is not a blanket exclusion of unrelated Rifts options with Mega in their names. Designing super vehicles and bases/headquarters is excluded. Buying or recording ordinary equipment/vehicles is still part of equipment support. Robot and bionic design remain required, including their character choices, resulting attributes/skills, components and costs; optional situational simulation does not become required through construction.

## Rules interpretations and execution

The agent is authorized to choose reasonable bonus ordering and resolve minor ambiguous prose. Record a short implementation note where useful; do not request a ruling for ordinary interpretation, manufacture an exhaustive contract for each edge case, or add mandatory override markers. Ask only when a choice materially changes product scope, loses user data, or crosses an actual permission boundary.

Implement coherent capability/content batches instead of individual maneuvers or tiny skill exceptions. Favor a few representative characters and expected skill percentages over exhaustive simulation. Use focused checks for the affected behavior, retain save/import/PDF safeguards, and run broad Windows/package verification at meaningful integration points. Avoid repeated identical full runs without a changed behavior or unresolved concern.

## Revised next priorities

1. Finish the small shared non-attribute ability selection adapter already underway; it supports descriptive abilities without inventing attribute effects.
2. Make the class/race import contract sufficient for attributes, skill grants/pools/percentages, ability choices/descriptions and equipment. Unsupported optional simulation does not block activation.
3. Expand available source options in batches using those shared definitions; prioritize class/race and skill coverage over combat refinements.
4. Validate representative creation, revision, advancement, save/reopen and editable-sheet workflows, then package and report remaining core gaps honestly.

The retrospective must compare the original plan with the delivered utility and explicitly identify this user-approved simplification. Do not portray optional details as outstanding required scope.

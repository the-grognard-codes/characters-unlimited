# Shared percentile skill-effect contract

Rule owners may declare `skill_effects` as a list of at most100 definitions. Each definition has exactly `id`, `name`, `operation`, `amount`, `selector`, and `source`. IDs are distinct within their owner; ID and name are nonempty text. The supported operation is `add`; amount is an integer within the shared safe whole-number range. A source requires nonempty book and section text; additional evidence metadata is retained.

The existing catalog selector resolves target identities, categories and canonical tags, with explicit missing references rejected and overlapping clauses deduplicated. Effects apply only to skills already projected by the existing acquisition/education/class adapters. They never grant a skill or selection credit. Separate effects add independently; explanations with the same display name accumulate their amounts while retaining distinct identities and source records in `effect_contributions`.

Rifts class profiles accept this field. Top-level Rifts effects belong to the default class; another profile has only its own declared effects and defaults to an empty list. Optional skills, fixed Domestic grants and required percentile skills use the same compiled targets. The target catalog combines available skills with required grant/choice definitions, using the first definition for each canonical identity. Heroes program packs and active mutant powers share the same effect engine. Power effect identities are namespaced by their owner; removing a power removes its projected skill effect while retaining its acquisition. All new power declarations, including inactive ones, validate before new power dice.

The percentile projection adds these amounts before its existing98% cap and additional-check rules. Existing education, learned levels, synergies and honor-system eligibility remain authoritative. Projected evidence derives from exact pinned definitions; it is not a new saved receipt. Portable reopening recomputes it from the embedded rules. Legacy power `skill_bonus` fields remain unchanged, including known missing references such as Interrogation. That compatibility path does not certify their dependencies.

This increment supports constant additive effects. Conditional targeting, random/retained skill-bonus acquisitions, level schedules, generic ability activation and full magic/psionic catalogs remain open. No new book definitions are accepted.

Typed power effect acquisition pins its skill catalog and education projection dependencies even before education is chosen. Portable import/export requires those exact pins and projects typed effects before accepting the character. Rifts creation also projects class effects before its first save. Primary and additional-check totals must remain within the shared exact integer range before publication, preventing browser rounding.

The Rifts and Heroes builders append each typed skill effect's display name, book/page citation and section to its skill explanation, using the same source formatter as attribute contributions. Legacy rows without typed effects retain their presentation.

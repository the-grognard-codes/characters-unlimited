# Owned class component preflight (22E5)

Opt-in `owned-v1` composition resolves all profiles and catalog references, then `preflight_owned_profiles` validates each resolved class before generation. Every error identifies the class and component. The pure preflight consumes definitions, not fake character state or random dice. Legacy overlays retain their existing behavior and no accepted archives change.

Supported checks: class source book/section; starting resource definitions, unique contributions/identities, known attribute terms, source book/section and complete formula bounds; distinct skill catalog identities and existing pool/count/cost, required-group and typed skill-effect validators; explicit supported pool/category field shapes, exact integer bonuses and known fixed skill grants; Physical grant identities/selectors, all retained formula groups, source evidence and known attribute/resource targets; default combat identity through the existing combat validator; both progression XP tables, ordinary HP die, level bounds, contiguous exact XP intervals, distinct related/secondary award levels, source evidence, known additional resources and safe possible gain totals.

Resource and Physical preflight functions live with those domains so future draft-import adapters can reuse the same validation. Every class-owned component is validated after shared catalog resolution; unselected profiles cannot hide invalid nested declarations. Selected/default mechanics, retained receipts, existing effects and portable pins remain unchanged.

Limits remain explicit. Required groups use their current validator; full proficiency, class-bonus arithmetic, source and conditional-combat schemas are not certified. Legacy allow/exclusion lists can describe options absent from the currently partial catalog, so this increment validates their shape and existing cost references without claiming full catalog completeness. Unreferenced catalog fragment mechanics, equipment/race/RCC composition, complete import activation and source-grounded two-class/nonhuman acceptance still need completion. An honor-system choice is retained; malformed supported rule data is an error.

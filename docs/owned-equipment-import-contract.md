# Class-owned equipment imports

Rifts equipment packs may opt into the existing `class_profile_format: owned-v1` format. Every supported class, including an explicit `default_class`, declares exactly `source`, `starting_funds`, `starting_gear`, `starting_choices` and `starting_groups`. All five are mappings. Source requires book/section evidence. An empty entitlement mapping explicitly means no grant and never inherits a default class entitlement.

The shared profile composer resolves whole-field ownership and source-bound `profile_catalogs` references. Item definitions and pack metadata stay shared. Nonempty entitlements identify their class owner and use the existing funds, personal gear, choice-set and independent-group formats. Every resolved profile runs the same public declaration compilers used by acquisition/projection, including unselected owners. Missing items, malformed formulas, unsupported ownership and missing evidence reject before initial dice or any equipment save. This extends class import composition without class-named handlers or parallel receipt logic.

Existing archives use their unchanged legacy composition. The common four-part starting-choice set now accepts its declared class owner instead of testing the Vagabond identity. This does not grant that set to other real classes. Its browser heading and unsupported guidance are generic. Supported group types remain the existing categories; components for robot/bionic construction and Heroes equipment remain separate required work.

Receipts, possession IDs, inventories, exact pins and portable reopening retain their established shape. Starting equipment still pins on first use; initial preflight does not invent a grant or equipment pin. Root class-owned fields are ignored in the owned format; unsupported selected classes require an explicit profile rather than inheriting default gear.

Six public workflow witnesses cover empty ownership, malformed unselected data before dice/save, current source-grounded Vagabond/City Rat grants and unchanged attributes/skills, book/section sources, shared catalogs and a deliberately synthetic non-Vagabond four-part choice set, exact portable receipts and current inventory. No accepted archive changes or broader class completeness certification are claimed. The current two-class content remains partial; future imports can use this schema directly. Race/R.C.C. composition, full maintainer conversion/activation reporting and broader class/category content remain required.

Owned starting funds can declare credits alone or credits plus saleable goods, with optional nonnegative `constant` and zero dice. The ordinary shared formula is `(sum of retained dice + constant) * multiplier`. Credits are required; all possible totals must be safe. Legacy archives retain their two-account shape. Browser and PDF explain constants and accept book/section-only citations; no saleable-goods row is invented.

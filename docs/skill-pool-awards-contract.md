# Named skill pool awards

An owned Rifts skill profile may add `level_awards` to one optional pool. The pool's existing `count` is its level-one allowance; each award adds its `count` at its declared level. For example, a pool with `count: 2` and awards of one choice at levels 3, 6, 9, and 12 permits six choices at level 12. Each award requires `source.book` and `source.section`. Levels are distinct exact integers from 2 through the profile's reviewed `higher_advancement.max_level`; counts are positive bounded exact integers. The whole schedule, including initial choices, is bounded by the retained learning history. An opted-in pool cannot also use the legacy `higher_advancement` award fields for that pool. Related and Secondary schedules without this opt-in retain their existing behavior.

Selections remain ordinary `skill_selections` entries. A source-defined `kind: training` catalog entry may set `requires_specialty: true` so each named type has its own retained `learning_levels` key. The projected row keeps its training description, source, specialty, and `learned_level`; it gains no invented percentage. The pool catalog exposes the award sources, while `remaining` and guidance show allowances and excess choices. Invalid declarations in an inactive owned profile reject before dice or persistence.

For a newly selected type, the engine reserves earned slots for current selections with retained learning ages, favoring the latest slot no later than each retained age. It assigns the earliest available attained slot to each new choice. Initial slots have age 1. If no slot remains, the choice receives the current level and remains visible with over-allowance guidance. Explicit player-supplied learning levels retain the existing honor-system override; an age earlier than the source allowance produces guidance. Removing and reselecting a type keeps its original learning key and age. Advancement, undo snapshots, export, import, and reopen carry those same keys without a new save field.

Pool credit retains the existing entry counting and duplicate guidance. A class requiring distinct initial types should declare a `requirements` rule with `counting: distinct-specialties` and an initial `before_level` cutoff. The browser offers automatic source dating for scheduled pools; choosing a numeric learned level explicitly overrides it. The editable PDF includes recorded skill learning ages in its notes.

The public `CharacterApplication` workflow tests in `tests/test_named_skill_pool_awards.py` use a synthetic archive and cover milestone ages, specialty descriptions, excess and explicit-early guidance, inactive declaration rejection, legacy separation, undo, and portable replay.

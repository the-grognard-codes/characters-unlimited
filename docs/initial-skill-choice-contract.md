# Initial skill choices and specialties

A source profile can declare `default_learned_level: 1` on an ordinary optional skill pool. Only the exact integer one is supported; booleans, other levels and malformed declarations reject during whole-profile preflight before dice or import writes. Archives without the field retain their current-level default.

The declaration supplies a default rather than rewriting history. An explicit player learning level takes precedence for a new acquisition. A previously recorded acquisition age remains authoritative when a skill is selected again, moved between pools, or imported. Required, fixed and automatic ordinary training continue to use the shared earliest-learning and strongest-class-bonus rules. Specialty identities use the existing normalized skill/specialty key, so a language does not become a different acquisition because its spelling changes case or surrounding whitespace.

The browser reads the pool metadata to initialize its learning-level control. Switching to an ordinary Related or Secondary pool restores the current-level default. The player can still select a different valid age. There is no class-name dispatch, approval gate or override marker.

Existing pool requirements can optionally declare `counting: distinct-specialties`. The default remains `distinct`, preserving historical declarations. The additional policy credits distinct eligible `(catalog identity, normalized specialty)` pairs. Skills without specialties use their catalog identity; a blank required specialty earns no requirement credit. Duplicate, ineligible and unfinished choices stay saved and visible. The eligible catalog-ID list remains available; the credited count and duplicate flag use qualified identities under the declared policy. Ordinary pool slot accounting still reports retained selection rows separately from the source requirement.

Requirements use the existing selector and pool-eligibility contracts. A source's additional MOS choices exclude its fixed/common grant IDs in the declaration; those fixed skills cannot fill an extra-choice requirement. Different complete specialties of the same eligible skill can fill separate choices. Invalid counting declarations reject before generation rather than silently adopting another policy.

The six initial Technical Officer MOS profiles use this shared contract. Their Related category access follows categories supplied by fixed MOS grants or eligible MOS choice categories; that access does not borrow the MOS choice bonus. Weapons MOS is available through its separate proficiency/equipment declarations; it does not add an initial MOS skill pool. This contract does not claim completion of the wider class, race/RCC, equipment, saved identity revision or construction plan.

# Accepted rule archives

`characters_unlimited/packs/accepted.json` separates the default versions for new characters (`active`) from every retained accepted definition (`definitions`). Each definition names its pack ID, version, filename inside the pack directory, and SHA-256 of canonical JSON. Canonical JSON uses sorted keys, UTF-8, finite values, and the serializer in `portability.canonical`; line-ending/indentation differences do not change content identity.

Accepted files are immutable records. A mechanical correction requires a new version and a separate file; retain the previous file and manifest entry. Editing an accepted file without changing its hash is rejected on application startup. Changing the active pointer affects new characters; saved characters retain their exact pins. Reads, rerolls, skill choices, duplicates, and portable bundles resolve those pins against the retained definitions. Unavailable versions produce diagnostics instead of substitution. The historical domestic version 1.0.0 pin for early unpinned saves remains the documented compatibility rule; it does not follow the active version.

The archive returns decoded copies of internally immutable canonical bytes. It is a storage/resolution contract for reviewed definitions, not a review or activation engine. The shipped manifest accepts implemented game core, Rifts skills/equipment and Heroes education/program contracts. Adding unknown operations or dependencies requires the schema/handler validation and review workflow in ticket 22. Do not add an unreviewed conversion to this manifest. Hashes establish identity within the reviewed installation, not external publisher signatures.

The first explicit correction adds the reviewed I.Q. skill bonus in domestic version 1.1.0. Version 1.2.0 additionally provides reviewed Vagabond grants and required choices; new characters use 1.2.0. Existing 1.0.0 characters retain their earlier projection until the player reviews and applies the update. The preview compares percentages and counts. Applying requires the preview's content token and saved revision, creates an exact pre-update SQLite backup, and changes the domestic pin in one transaction. Backup or update failure leaves the prior save intact. The README documents manual restoration of that backup.

Core/other-pack preview/apply upgrades and both-game compatibility remain in 18B. Tests also use artificial archived versions as fixtures to prove that changing active definitions cannot silently change existing calculations or replace their exported provenance; these fictional versions are not included in the production manifest.

Skill previews pair grants and selections by identity, specialty, and occurrence, and include secondary horsemanship checks. Adding grants cannot misalign the before/after values of existing selections. Required-choice counts are included in the preview; no existing choice or recorded attribute roll is changed by the update.

Rifts skills 2.0.0 introduces recorded Physical acquisitions. Compatible catalog updates preserve dice, active modifiers and historical snapshots. Preview rejects changes to any acquired Physical definition, including an inactive acquisition, until a dedicated migration can preserve its provenance. Physical preview rows carry an empty unit instead of a percentage. This restriction keeps parent 18 open; it does not silently apply new formulas to old dice.

Rifts equipment 1.0.0 is pinned on the first explicit inventory action, alongside the existing game/skill pins. Inventory writes, reopening, duplication and portable bundles use that exact version. The active catalog may be browsed before a character has possessions; viewing does not mutate its pins. Explicit equipment-rule corrections now join the Rifts preview. Changed catalog fields, carried weight and active attacks are shown before all changed pins are applied atomically with a backup. Credits, possessions and ammunition remain recorded; incompatible missing items or decreased capacities require a separate migration and are rejected. See the equipment contract for the reviewed bounded schema and remaining contexts.

Heroes program `choice_groups` may declare `selection_costs` mapping eligible skill IDs to positive whole selection costs; omitted IDs cost one. The source-reviewed Physical/Athletic group uses count4, Expert2, Martial Arts3 and Assassin3. Its projection's `credited` sums costs of distinct eligible IDs; duplicates and outside-group choices remain recorded but do not fill additional entitlements. Earlier groups without costs retain their distinct-choice behavior. The browser and editable PDF show weighted budgets, costs and source references. This reviewed extension does not activate arbitrary imported operations; the external pack schema/validation workflow remains ticket22.

A reviewed program may declare `repeat_entitlement_pending: true`. Its repeated entries retain choices but project `credit_certified: false`, zero credited choices, and no new group grants; first entries retain their normal behavior. Existing programs without the flag keep their earlier contract. Physical/Athletic uses this explicit pending state until remaining-category repeat rules are reviewed.

Heroes Physical percentile definitions may name a `primary_check_name` and declare a standalone additional check's `per_level`; omission keeps the primary rate. A check's `unless_skill` names the ordinary acquired skill that replaces its fallback ability. Source-bound `skill_bonuses` on an acquired Physical definition declare target `skill_id` and percentage `amount`; these bonuses apply once from credited Physical grants, including retained honor-system Secondary choices. Acrobatics uses this bounded contract for Climbing/Rappelling and Prowl while preserving their earlier immutable definitions. Outside-group and uncertified repeated-program Physical choices retain entered selections but produce no Physical proficiency or modifier. This shipped extension does not activate imported operations; external schema/review remains ticket22. Heroes advancement remains pending.

Gymnastics declares `shared_check_skill_ids: ["acrobatics"]`, bound to its acquired definition and original printed47/PDF48 shared-ability rule. When both training skills have credited grants, the shared-ability projection retains each source check and selects the highest calculated proficiency for a duplicated name; it never sums percentages or education. Ties use reviewed catalog order. The browser and editable sheet show each effective ability once from its winning source, while the application view retains raw checks and origins. A Secondary winner retains zero education bonus. Single-training views and older packs remain unchanged; changing acquired Gymnastics shared rules is rejected by the full-definition migration guard.
